# Chai aur Django ☕

A Django web project built while learning Django with the **"Chai aur Django"** tutorial series. What started as a basic multi-page app has grown into a small "chai shop" application that demonstrates:

- Views, URL routing (including dynamic path converters) and template inheritance
- Static files and **Tailwind CSS** (via `django-tailwind`) with live browser reload
- **Models covering all three ORM relationship types** (One-to-Many, Many-to-Many, One-to-One)
- Image/media uploads with **Pillow**
- A customized **Django Admin** (inlines, list display, filter widgets)
- **Forms** with POST handling and validation

Django version: 6.1.1 · Python version: 3.14

## Getting Started

### Prerequisites

- **Python 3.14+**
- **Node.js / npm** — required by django-tailwind to compile CSS
- **uv** — Python package manager (optional but recommended)

### 1. Create and activate a virtual environment

```bash
# Install the uv package manager (one time)
pip install uv

# Create a virtual environment at .venv
uv venv

# Activate it
# On Windows (PowerShell):
.venv\Scripts\activate
# On macOS/Linux:
source .venv/bin/activate
```

### 2. Install the Python dependencies

```bash
uv pip install Django django-tailwind django-browser-reload Pillow
```

### 3. Project scaffolding (already done in this repo)

These steps were already completed — they are listed for reference (see `commands.txt` for the full command history):

```bash
# Create the project
django-admin startproject chaiaurDjango

# Create the chai app
py manage.py startapp chai

# Initialize the Tailwind theme app
py manage.py tailwind init

# Install npm dependencies for Tailwind (inside theme/static_src)
py manage.py tailwind install
```

### 4. Apply database migrations

```bash
py manage.py makemigrations chai
py manage.py migrate
```

### 5. Create a superuser (for the admin site)

```bash
py manage.py createsuperuser
```

## Running the Development Server

Run the Tailwind watcher and the Django dev server (two terminals):

```bash
# Terminal 1 — rebuilds Tailwind CSS on change
py manage.py tailwind start

# Terminal 2 — starts Django
py manage.py runserver
```

The app is served by default on `http://127.0.0.1:8000/`. To run on a different port:

```bash
py manage.py runserver 8001
```

- `django-browser-reload` is installed as middleware, so pages refresh automatically when templates, Python code or CSS change.
- Uploaded media is served at `/media/` while `DEBUG = True`.
- The admin site is available at `http://127.0.0.1:8000/admin/`.

## Application Overview

### The `chai` app — models & relationships

The `chai` app (registered in `INSTALLED_APPS`) contains four models that together demonstrate every ORM relationship type:

```
ChaiVarity ◄─── (One-to-Many) ─── ChaiReview       (ForeignKey + related_name='reviews')
ChaiVarity ◄─── (Many-to-Many) ── Store            (ManyToManyField + related_name='stores')
ChaiVarity ◄─── (One-to-One) ──── ChaiCertificate  (OneToOneField + related_name='certificate')
```

| Model | Relationship | Key fields |
|-------|--------------|------------|
| `ChaiVarity` | — | `name`, `image` (`ImageField`, uploads to `chais/`), `date_added`, `type` (choices: MASALA, GINGER, KIWI, PLAIN, ELACHI), `description` |
| `ChaiReview` | **One-to-Many** → `ChaiVarity`; FK to `auth.User` | `chai`, `user`, `rating`, `comment`, `date_added` |
| `Store` | **Many-to-Many** → `ChaiVarity` | `name`, `location`, `chai_varieties` |
| `ChaiCertificate` | **One-to-One** → `ChaiVarity` | `chai`, `certificate_no`, `issued_date`, `valid_untill` |

All models live in `chaiaurDjango/chai/models.py`; migrations `0001`–`0003` in `chai/migrations/` create their tables.

### Views

Defined in `chaiaurDjango/chai/views.py`:

- `all_chai` — lists every `ChaiVarity` in a Tailwind card grid.
- `chai_detail(request, chai_id)` — fetches a single variety with `get_object_or_404` and renders its details.
- `chai_store_view` — renders a **form** (`ChaiVarityForm`); on a valid **POST** it queries `Store.objects.filter(chai_varieties=...)` and lists the matching stores.

### Forms

`chaiaurDjango/chai/forms.py` defines `ChaiVarityForm` — a plain `forms.Form` with a `ModelChoiceField` bound to `ChaiVarity.objects.all()`. It demonstrates form rendering (`{{ form.as_p }}`), CSRF protection, `form.is_valid()` and `form.cleaned_data`.

### Django Admin

Customized in `chaiaurDjango/chai/admin.py`:

| Model | Admin class | Customization |
|-------|-------------|---------------|
| `ChaiVarity` | `ChaiVarietyAdmin` | `list_display` (name, type, date_added) + `ChaiReviewInLine` (`TabularInline`, `extra=2`) so reviews are edited on the same page |
| `Store` | `StoreAdmin` | `list_display` (name, location) + `filter_horizontal` widget for the many-to-many field |
| `ChaiCertificate` | `ChaicertificateAdmin` | `list_display` (chai, certificate_no) |
| `ChaiReview` | — | Not registered directly; edited through the inline on `ChaiVarity` |

### URL Routes

Root config in `chaiaurDjango/chaiaurDjango/urls.py`, app routes in `chai/urls.py`:

| Route | View | Name | Template / Response |

| `/` | `views.home` | `home` | `website/index1.html` |

| `/__reload__/` | django-browser-reload | — | Live-reload endpoint |
| `/media/...` | `static()` helper | — | Uploaded media (DEBUG only) |

### The `theme` app (Tailwind CSS)

Created by `py manage.py tailwind init` and wired up in `settings.py` via `TAILWIND_APP_NAME = 'theme'`:

- `theme/static_src/src/styles.css` — Tailwind v4 entry point (`@import "tailwindcss"` plus an `@source` directive that scans all `.html`, `.py` and `.js` files for utility classes).
- `theme/static/css/dist/styles.css` — the compiled CSS output, loaded on every page through the `{% tailwind_css %}` tag.
- `NPM_BIN_PATH` in `settings.py` points to `npm.cmd` (Windows-specific npm path).

### Templates

- `templates/layout.html` — base template: loads `static/style.css` and `{% tailwind_css %}`, provides the `title` and `content` blocks used by every page.
- `templates/website/index1.html` — home page extending `layout.html`.
- `chai/templates/chai/all_chai.html` — 3-column Tailwind grid of chai cards (image, name, button linking to the detail page).
- `chai/templates/chai/chai_detail.html` — shows a variety's name and description.
- `chai/templates/chai/chai_stores.html` — the store-search form plus the results list.
- `theme/templates/base.html` — sample page from django-tailwind (not used by the main pages).

### Static & Media Files

- `static/style.css` — plain-CSS dark theme applied globally via the base layout (`STATICFILES_DIRS`).
- `media/chais/` — images uploaded through the admin via `ChaiVarity.image`, served at `/media/` in development.

### Key Settings (`chaiaurDjango/chaiaurDjango/settings.py`)

- **Installed apps:** `chai`, `tailwind`, `theme`, `django_browser_reload` (plus Django's defaults)
- **Middleware:** includes `BrowserReloadMiddleware`
- **Database:** SQLite (`db.sqlite3`)
- **Templates:** `DIRS = ['templates']` (project-level) + `APP_DIRS` (app-level `chai/templates/`)
- **Static files:** `STATIC_URL = 'static/'`, `STATICFILES_DIRS = [BASE_DIR / 'static']`
- **Media:** `MEDIA_URL = '/media/'`, `MEDIA_ROOT = BASE_DIR / 'media'`
- **Tailwind:** `TAILWIND_APP_NAME = 'theme'`, `INTERNAL_IPS = ['127.0.0.1']`, `NPM_BIN_PATH` (Windows npm path)
- **Email backend:** console (for development)
- **Password validators:** default Django set enabled

## Notes

- The project uses **uv** for fast package installation and virtual environment management; the `.venv` lives at the repo root.
- `db.sqlite3`, `media/`, `.venv/` and `__pycache__/` are excluded from version control via `.gitignore`.
- Media is served by `static(settings.MEDIA_URL, ...)` in `urls.py`, which only works while `DEBUG = True` — a production deployment would need a real media/web server.
- `DEBUG = True` and a hardcoded development `SECRET_KEY` are fine for learning, but must be changed before any real deployment.
